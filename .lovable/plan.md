# Авторизация и управление пользователями в Annuli

## Цель

Добавить вход в приложение через Google, Apple и электронную почту, профили пользователей с ролями (админ/пользователь) и админ-страницу управления учётными записями (список, блокировка). Генеалогическая база остаётся локальной (IndexedDB) — облако используется только для учётных записей.

## Шаги

### 1. Включение Lovable Cloud
- Активировать Lovable Cloud (автоматически создаётся бэкенд: база PostgreSQL + система аутентификации).
- Включить провайдеров входа: Google и Apple (через настройку социальной авторизации), email/password включён по умолчанию.

### 2. Таблицы в облачной базе (миграция SQL)
- `public.profiles` — id (связь с пользователем), отображаемое имя, email, аватар, флаг `is_blocked`, даты создания/обновления.
- `public.user_roles` + enum `app_role` ('admin', 'user') — роли строго в отдельной таблице.
- Функция `has_role(user_id, role)` (security definer) для проверок без рекурсии RLS.
- RLS-политики: пользователь читает/обновляет только свой профиль; список всех профилей и блокировку может делать только админ.
- Триггер: при регистрации автоматически создаётся запись в `profiles`; первому пользователю (или указанному email Дмитрия) выдаётся роль `admin`, остальным — `user`.

### 3. Экраны входа
- Страница `/auth` (публичная, в стиле тёмной темы приложения): кнопки «Войти через Google», «Войти через Apple», форма email + пароль (вход/регистрация), восстановление пароля.
- Страница `/reset-password` для установки нового пароля из письма.

### 4. Защита приложения
- Защищённый layout `_authenticated`: неавторизованный пользователь перенаправляется на `/auth`; заблокированный пользователь (`is_blocked`) видит экран «Доступ ограничен» вместо приложения.
- В шапке приложения: меню пользователя (аватар/имя) с пунктами «Профиль», «Управление пользователями» (только для админа) и «Выйти».

### 5. Личный кабинет (`/profile`)
- Просмотр и редактирование отображаемого имени, смена пароля (для email-аккаунтов), выход.

### 6. Админ-страница (`/admin/users`, только для роли admin)
- Таблица пользователей: имя, email, роль, дата регистрации, статус (активен/заблокирован).
- Действия: заблокировать/разблокировать пользователя. Блокировка хранится в `profiles.is_blocked` и проверяется при входе в приложение.

### 7. Проверка
- Вход по email (регистрация → подтверждение → вход), вход через Google, блокировка пользователя админом, корректный выход и повторный вход.
- Локальные данные IndexedDB не затрагиваются — после входа база персон открывается как раньше.

## Технические детали

- Lovable Cloud предоставляет встроенную аутентификацию (Supabase под капотом): email/password, Google, Apple — без внешних аккаунтов и настройки OAuth вручную.
- Маршруты: `src/routes/auth.tsx`, `src/routes/reset-password.tsx` (публичные); основной контент переезжает под `src/routes/_authenticated/` с интеграционным гейтом.
- Серверные функции с `requireSupabaseAuth` для админ-действий (список пользователей, блокировка) — проверка роли `admin` на сервере, не в браузере.
- Текущий `src/routes/index.tsx` останется главной страницей приложения, но будет защищён; публичной станет только страница входа.
