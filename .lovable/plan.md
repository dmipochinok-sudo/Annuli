# CMS «Изображения»: загрузка файлов вместо ссылки

## Цель
Перейти от ручной вставки ссылки к загрузке изображения с компьютера в публичный Storage-бакет, с сохранением подписей RU/EN, превью и сброса к исходному изображению. Касается только публичного сайта и CMS. Авторизация, база персон, кабинеты, `/app`, окружение и существующие RLS не меняются.

## Предварительное условие
- Владелец/админ workspace разрешает публичные бакеты: **Settings → Privacy & Security** (настройки рабочего пространства) — снять блок `cloud_block_public_buckets`.
- Если переключатель всё ещё блокирует, создание публичного бакета вернёт ошибку и я остановлюсь, ничего не ломая.

## Шаг 1. Создать публичный бакет `site-assets`
- Инструмент `supabase--storage_create_bucket`: name=`site-assets`, public=true, file_size_limit=`5MB`.
- Существующий приватный бакет `annuli-media` (материалы персон) не трогаем.

## Шаг 2. RLS на `storage.objects` (миграция)
Через `supabase--migration`. Только для бакета `site-assets`:
- `SELECT` для `anon, authenticated` — `USING (bucket_id = 'site-assets')` (публичное чтение).
- `INSERT/UPDATE/DELETE` для `authenticated` — `USING (bucket_id = 'site-assets' AND public.is_admin())` и `WITH CHECK (bucket_id = 'site-assets' AND public.is_admin())`.
- Используется существующая `public.is_admin()`. Новых ролей не создаём.
- Запись анонимов запрещена. Существующие политики на `annuli-media` не меняем.

## Шаг 3. Переделать вкладку «Изображения» (`src/components/site/cms/AssetsTab.tsx`)
Полная замена поля ссылки на загрузку файла:
- Убрать `<input>` ссылки; добавить кнопку «Загрузить» (`<input type="file" accept="image/png,image/jpeg,image/webp">`, скрытый, открывается по клику).
- Клиентская валидация: тип ∈ {png, jpeg, webp} (SVG запрещён), размер ≤ 5 МБ; при нарушении — `toast.error` без запроса.
- Загрузка: `supabase.storage.from('site-assets').upload(path, file, { upsert: true, contentType })`, путь `hero-image.<ext>` / `logo-image.<ext>`, затем `getPublicUrl(path)` → публичный URL.
- После загрузки: `upsert` в `site_assets` (key, url, alt_ru, alt_en, updated_at) как сейчас; инвалидация `["site-assets"]`; `toast` успех/ошибка.
- Превью — из загруженного URL (или `heroAsset.url` для hero по умолчанию).
- Поля alt RU/EN и кнопка «Сбросить» остаются: сброс удаляет запись в `site_assets` (файл в Storage НЕ удаляем автоматически — безопасно), сайт возвращается к исходному изображению.
- Состояния: выбор файла, загрузка, сохранение, ошибка.

## Шаг 4. Публичное отображение (без изменений логики)
- `sections.tsx` → `Hero` уже берёт `hero_image` из `site_assets` с fallback на `heroAsset.url`. Загруженный публичный URL будет отображаться как есть. Логику не трогаем.
- Слот `logo_image` остаётся хранимым (на сайте логотип — SVG-марка `Logo.tsx`); рендер логотипа из базы в эту итерацию не вводим.

## Шаг 5. Стили
- В `src/styles.css`/`annuli-design-system-v2.css` добавить минимальные классы для файловой кнопки и состояния загрузки, в существующем визуальном языке CMS (`.cms-img-up`, индикатор). Без редизайна.

## Шаг 6. Проверка
- Typecheck `npx tsgo --noEmit`.
- Playwright под админ-сессией: загрузить hero-фото (JPEG ≤5МБ), проверить появление на главной и в превью; сброс — возврат к исходному; попробовать PNG/WebP и файл >5МБ / SVG → отказ; проверить, что аноним не может писать в бакет.
- Обновить `legacy/ANNULI_PROJECT_DOCUMENTATION.md`.

## Не меняется
Авторизация, Supabase Auth, `.env`/`.env.example`, таблицы profiles/user_roles/site_content, существующие RLS, защищённые маршруты, кабинеты, `/app`, приватный бакет `annuli-media`, база персон, роли. Платежей/рейтингов нет.

## Результат для пользователя
В разделе «Изображения» CMS вместо поля ссылки — кнопка «Загрузить»: выбираете файл с компьютера (PNG/JPEG/WebP до 5 МБ), он сохраняется в публичное хранилище и сразу показывается на главной. «Сбросить» возвращает исходное фото героя. Логотип по-прежнему SVG-марка; слот логотипа хранится, но не выводится.
