# Кабинет специалиста, карточки специалистов на главной и собственные базы

## 1. Кабинет специалиста (/account для роли «Специалист»)
Пять пронумерованных разделов слева, как в ваших примерах:

- **01 Карточка** — аватар (квадрат, до 256 px), переключатели «Видимость карточки» и «Принимает новых клиентов», кнопка «Предпросмотр»; специализация RU/EN, «О себе» RU/EN, регионы работы, архивы, виды деятельности. Отметка статуса: «Опубликована» / «Скрыта».
- **02 Тарифы** — список услуг специалиста: тип (фиксированный / по договорённости), название RU/EN, цена RU/EN, срок RU/EN, «что входит» RU/EN; добавить и удалить. Подсказка: минимум 2 фиксированных и 1 открытый тариф.
- **03 Отзывы** — отзывы клиентов о специалисте (дата, имя, текст, отметка «подтверждённый заказ»); специалист может ответить и сохранить ответ. Оставлять и публиковать отзывы будет следующим этапом (модерация в CMS); сейчас раздел показывает опубликованные отзывы и ответы.
- **04 Базы** — две группы:
  - **Мои базы** — специалист создаёт собственные родословные базы (название), видит число персон, открывает в приложении и удаляет (с подтверждением; удаляются персоны и файлы этой базы). Кнопка «Создать базу» недоступна, когда лимит тарифа исчерпан.
  - **Клиентские базы** — базы, к которым клиенты выдали доступ: статус, уровень, срок, владелец, «Открыть приложение».
- **05 Лимиты** — тариф специалиста (по умолчанию FREE), счётчик «Базы: 1 / 10», хранилище «1 ГБ».

Клиентский кабинет остаётся как сейчас.

## 2. Карточки специалистов на главной
- Новый раздел «Специалисты» в стиле вашего макета: сетка 3×2, **ровно до 6 карточек** — фото, «Специалист по генеалогии», ФИО, специализация, архивы, «Перейти в профиль →».
- Нажатие открывает окно с публичной информацией: фото, ФИО, «О себе», данные (специализация, регионы, архивы, виды деятельности), тарифы, отзывы.
- Показываются только специалисты, которых отобрали администратор или владелец, и только если специалист сам сделал карточку видимой. Никакие личные данные (почта, телефон) не показываются.
- Раздел получает переключатель видимости во вкладке CMS «Блоки», RU/EN.

## 3. CMS — новая вкладка «Специалисты»
Для администраторов и владельцев:
- список всех специалистов с отметками «Видима», «Принимает клиентов»;
- **добавить на главную / убрать с главной**, стрелки порядка ↑/↓, счётчик «выбрано N из 6» (седьмую добавить нельзя);
- тариф специалиста (FREE и т. п.) и лимит баз — меняет владелец/админ;
- все действия пишутся в «Журнал».

## 4. Несколько баз у одного пользователя
Сейчас у каждого пользователя одна общая база персон. Вводятся именованные базы:
- существующие персоны каждого пользователя автоматически переносятся в его первую базу («Моя база») — данные не теряются;
- приложение открывает выбранную базу; доступы клиентов к специалистам продолжают работать как раньше.

## Порядок работ
1. Данные: публичная карточка, тарифы, отзывы, базы, отбор на главную, лимиты; перенос существующих персон.
2. Кабинет специалиста (5 разделов), создание и удаление баз с проверкой лимита.
3. Раздел «Специалисты» на главной и окно профиля.
4. Вкладка CMS «Специалисты».
5. Живая проверка: специалист заполняет карточку и создаёт/удаляет базу; админ выводит его на главную; карточка видна посетителю. Обновление документации.

## Что не меняется
Вход и регистрация, роли и их логика, клиентский кабинет, остальные вкладки CMS, онлайн-оплаты (не подключаем).

## Технические детали
- `specialist_profiles` (user_id PK, avatar_url, specialization_ru/en, about_ru/en, regions_ru/en, archives_ru/en, activities_ru/en, is_visible, accepts_clients, featured bool, featured_order int, plan text default 'free', bases_limit int default 10, storage_limit_mb default 1024). RLS: специалист правит свою строку, кроме featured/featured_order/plan/limits (контроль через триггер); админ — всё. Публичное чтение только через SECURITY DEFINER `list_featured_specialists()` (featured AND is_visible, limit 6, безопасные колонки + ФИО из profiles).
- `specialist_rates` (id, user_id, kind fixed|open, name/price/term/includes _ru/_en, sort_order); публичное чтение для карточек из выборки featured.
- `specialist_reviews` (id, specialist_id, client_id, body, reply, is_published, order_confirmed, created_at); специалист обновляет только `reply`.
- `genealogy_bases` (id, owner_id, title, created_at); `persons.base_id` → миграция создаёт по одной базе на каждого владельца и проставляет base_id. Триггер лимита на INSERT по `bases_limit` (клиентам — 1 по умолчанию). Удаление базы каскадно удаляет persons; файлы в `annuli-media` удаляются клиентом по префиксу базы.
- `db.ts`/`useAnnuli` принимают `baseId`; маршрут `/app?base=…` (совместимость с `?owner=`: берётся первая база владельца).
- Аватары — в публичном бакете `site-assets` в папке `specialists/{user_id}/`, запись только владельцу папки и админам.
- UI: `SpecialistCabinet` в `src/components/site/cabinet/`, `SpecialistsSection` + диалог в секциях лэндинга, `SpecialistsTab` в CmsPanel; ключ секции `specialists` в `site_sections`.
