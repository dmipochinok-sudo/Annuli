# Перенос базы Annuli в облако с разделением по пользователям

Сейчас все данные лежат в браузере устройства (IndexedDB), поэтому любой вошедший пользователь видит одну и ту же базу. Переносим персон и сканы в облако с привязкой к владельцу.

## Что получится

- У каждого пользователя своя изолированная база персон и своих сканов/фото.
- Данные видны на любом устройстве после входа — база больше не привязана к браузеру.
- Администратор может выбрать любого пользователя в списке «Управление пользователями» и открыть его базу, работая с ней как со своей (с явной плашкой «Вы работаете в базе: Имя»).
- Экспорт/импорт ZIP + GEDCOM сохраняется: импорт заливает данные в облачную базу текущего (или выбранного админом) пользователя.
- Локальная база IndexedDB больше не используется как источник данных. Перенос существующих данных — вручную: выгрузить ZIP из старой версии и импортировать после входа.

## Структура данных в облаке

- Таблица персон: владелец, индекс персоны, имя (для поиска и сортировки), полная карточка персоны как единый документ, даты создания/обновления.
  Формат карточки остаётся ровно таким же, как сейчас в приложении, — вкладки, документы, альбомы менять не нужно.
- Приватное хранилище файлов для сканов и фото: файлы каждого пользователя лежат в отдельной папке по его идентификатору.
- Правила доступа: пользователь видит и меняет только свои строки и свои файлы; администратор — любые. Никакого публичного доступа.

## Технические детали

1. Миграция БД: таблица `public.persons` (`id uuid`, `owner_id uuid`, `person_index text`, `full_name text`, `data jsonb`, `created_at`, `updated_at`), индексы по `owner_id` и `person_index`, GRANT для `authenticated`/`service_role`, RLS: own-row по `auth.uid() = owner_id` (SELECT/INSERT/UPDATE/DELETE) плюс админские политики через `private.has_role(auth.uid(),'admin')`. Триггер `updated_at`.
2. Приватный bucket `annuli-media` (файлы по ключу `{owner_id}/{imageId}`), политики на `storage.objects`: доступ по совпадению первого сегмента пути с `auth.uid()` либо для админа.
3. Новый модуль `src/lib/annuli/cloud.ts` с тем же API, что и текущий `db.ts`: `dbAllPersons/dbPutPerson/dbDelPerson/imgPut/imgGet/imgDel`, но с параметром «владелец базы». Вызовы идут через браузерный клиент — RLS сама изолирует данные. Все существующие компоненты (`PagesEditor`, `PersonAlbums`, `BirthDocSection`, `archive.ts`, `person-export.ts`) продолжают работать без изменений логики: меняется только импорт слоя доступа.
4. Контекст активной базы: `src/hooks/use-annuli.ts` получает `ownerId` (по умолчанию — текущий пользователь; для админа — выбранный из `?owner=` в маршруте). Загрузка персон переводится на TanStack Query с ключом, включающим `ownerId`.
5. Кэш `use-image-url.ts` переводится на подписанные URL из облачного хранилища (с TTL и локальным кэшем в памяти), сохраняя текущий интерфейс хука.
6. В `admin/users.tsx` добавляется действие «Открыть базу» → переход на главную с выбранным владельцем; в шапке — индикатор чужой базы и кнопка «Вернуться в свою».
7. Старый `db.ts` остаётся только для одноразового вспомогательного экспорта локальных данных («Скачать локальную базу как ZIP») в диалоге «База данных», чтобы пользователь мог перенести накопленное вручную.
8. Импорт ZIP/GEDCOM в `archive.ts` пишет персоны и файлы в облако пачками с индикатором прогресса; экспорт читает из облака.

## Ограничения

- Требуется вход: без авторизации данные не загружаются.
- Работы офлайн не будет — при отсутствии сети приложение покажет ошибку загрузки.
- Загрузка больших наборов сканов зависит от скорости сети; импорт делается пакетно с прогрессом.
